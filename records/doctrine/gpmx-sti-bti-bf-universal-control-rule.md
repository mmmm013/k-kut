# GPMx / GPEx / 4PE Universal STI-BTI-BF Control Rule

## Core rule

Some items must exist for the system to function.

Those required items are STIs.

STIs may be front-end, back-end, release-gate, outlet, processing, padding, signature, delivery, review, routing, proof, or operational-control items.

An STI is not optional merely because it is not a buyer-facing product.

## STI

STI means the controlled must-exist item or standard object entering the system.

STIs include, without limitation:

- Padding
- Twinkle
- DP / Delivered Present / delivery-present mechanics
- release-gate requirements
- review-gate requirements
- payment-process requirements
- opt-in / compliance requirements
- fulfillment requirements
- routing requirements
- inventory-index requirements
- safety / tone gates
- canonical identity requirements

## STI-Slot

An STI-Slot is the controlled holding position for a required item before it is operationally used.

Nothing becomes active merely because it exists.

The STI-Slot holds the item until classification, BTI assignment, registry linkage, outlet placement, and release authority are ready.

## BTI

BTI means Brand + Behavior Template / Branding Template Standard.

BTI identifies:

- brand role
- behavior role
- naming rule
- display rule
- promise rule
- required wording
- forbidden implication
- allowed placement
- blocked placement
- timing rule
- outlet rule
- release condition

## BF

BF is the guard filter.

BF blocks wrong naming, wrong placement, wrong timing, wrong promise, wrong outlet, wrong context, and unauthorized release.

Fail closed when required facts, readiness, authority, or BTI are missing.

## GPMx application

GPMx operates within 4PE-ALL.

GPMx uses STIs and STI-Slots for universal required operating items.

GPMx uses BTIs to define Brands and Behaviors.

GPMx uses BF to block wrong use before Release Gate / Outlet.

## K-KUT / HUG / TUG / BUG application

K-KUT and Short-KUT are product families.

HUG, TUG, and BUG are intent containers.

BUGs are user-demand interchangeable products and must not consume STI identity.

Padding, Twinkle, and DP are STIs and must be reviewed as system-operating items.

Padding, Twinkle, and DP may support K-KUT/HUG/TUG/BUG flows only after STI-Slot, BTI, BF, and release/outlet approval.

## BUG review rule

BUG approval review must not approve system STIs as BUG products.

A BUG candidate must be a real BUG-safe Short-KUT / tiny KUT.

A system STI may be useful, necessary, and urgent, but it is not a BUG unless explicitly approved through BTI for BUG use.

## VOC rule

Additional homonym/product/container concepts may be added later only by VOC evidence, owner approval, STI intake, BTI definition, BF guardrail, and release gate.
