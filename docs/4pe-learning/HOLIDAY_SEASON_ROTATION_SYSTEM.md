# Holiday + Calendar Season Rotation System

## Locked Context

Mother’s Day was the prototype and is independently released as planned.

The next system is not “make another one-off holiday page.”

The next system is:

Holiday rotation + calendar season rotation + evergreen use cases + weekly exposure balancing.

## Core Rule

Holiday promos rotate.

Evergreen buyer use cases remain available.

Between holiday windows, calendar seasons carry the buyer story.

Calendar seasons should feel traditional enough to understand, but advanced, contemporary, and evolving.

## Four Rotation Layers

1. Specific holiday
2. Calendar season
3. Evergreen use case
4. Weekly exposure balancer

## KKr Metadata Doctrine

PIX metadata helps, but it is partial.

KK metadata must carry most buyer-match weight.

KKr must run multiple labeling loops:

- occasion
- relationship
- POV
- emotional level
- phrase / lyric meaning
- buyer intent
- promo suitability
- exclusion law
- weekly exposure balancing

## Search-to-Match Rule

Search-to-Match has no hard limit.

But when helpful, weekly exposure balancing should prevent the same few IIs from dominating every live route.

## Candidate Laws

No INSTRO.

No direct same-holiday LT-PIX by default.

No Music Maykers in public UI.

No mKs / mini-KUTs in public buyer flow unless ADMIN override is active.

No duplicate II unless ADMIN explicitly directs it.

Customer delivery audio requires padding and Twinkle together.

## Father’s Day Next

The strict Father’s Day scan found registry/text signal but no direct clean audio-by-path shortlist yet.

Next work is to convert the strongest Father’s Day registry/text candidates into real delivery candidates.
