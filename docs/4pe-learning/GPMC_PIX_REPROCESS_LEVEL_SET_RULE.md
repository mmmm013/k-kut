# GPMC / 4PE-BIZ-MSC PIX Reprocess Level-Set Rule

## Locked Rule

4PE-BIZ-MSC must re-process ALL PIX / LT-PIX inventory at KK depth.

The system must not stop at PIX counts.

The system must ask:

How many usable KKs exist across each PIX / LT-PIX source?

Each PIX may yield multiple KKs.

## Core Distinction

PIX / LT-PIX:
- source-level inventory
- not itself buyer option count
- may feed many KKs

KK:
- selected/cut music moment
- buyer/product candidate layer
- must be analyzed, labeled, classified, and routed by use case
- not public product until materialized as II

II:
- finished customer-ready delivery audio object
- must contain padding and Twinkle baked into the file
- public buyer pages may only play finished II files

CI:
- Cost Item
- financial/sellable item tied to a customer-satisfying II or II-based offer

DP:
- Delivery Package
- governed fulfillment package triggered by buyer request and finalized by payment

## KK-First Reprocess Standard

For every PIX / LT-PIX, KKr / MSC must:

1. refresh source record
2. scan structure
3. identify all plausible KKs
4. separate KKs from KK-Kombos
5. label KKs by buyer use case / feeling / intent
6. classify public-readiness
7. mark whether II materialization is needed
8. prevent raw PIX / raw KK public playback
9. materialize selected KKs into finished IIs only after approval
10. connect finished IIs to CI / DP only after QA/QC

## KK vs KK-Kombo

KK:
- single selected/cut music moment
- primary public candidate type for K-KUT buyer flow

KK-Kombo:
- combined or assembled multi-KK product candidate
- may use similar processing logic
- must remain separate from public k-kut.com buyer flow for now

## Public k-kut.com Rule

Do not expose KK-Kombos publicly on k-kut.com until sales take hold and ADMIN explicitly approves.

Public k-kut.com buyer flow may use:

- finished IIs
- CI / DP offers
- approved single-KK-derived II delivery audio

Public k-kut.com buyer flow may not use:

- raw PIX audio
- raw KK audio
- KK-Kombos
- mKs / mini-KUTs
- runtime padding
- runtime Twinkle

## Father’s Day Correction

Father’s Day depth must be counted by KKs, not PIXs.

A source such as “No Mystery” may yield several usable KKs.

The process must surface those KKs individually as candidates.

The bottleneck is not source count.

The bottleneck is converting approved KKs into finished II delivery files.

## Always-On Depth

4PE-BIZ-MSC / GPMC-C is intended to run at this depth for ALL LT-PIX inventory.

This is not a one-time Father’s Day fix.

This is the level-set for the whole catalog.
