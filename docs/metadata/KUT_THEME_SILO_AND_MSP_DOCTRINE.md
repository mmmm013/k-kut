# KUT Theme Silo and MSP Doctrine

Status: CURRENT DOCTRINE

## Core law

All KUTs / KKs may exist in multiple themes.

Theme membership is many-to-many.

A theme silo does not create a KUT.

A theme silo does not detach a KUT from its PIX.

A theme silo is a lookup and prioritization view over existing exact-audio KUTs.

## Source structure

PIX is the source authority and SSOT.

KUT / KK is the exact audio excerpt from the PIX.

Theme silo maps existing KUTs / KKs to end-user needs.

MSP route presents useful, safe, user-focused choices.

## Theme silo purpose

A theme silo answers:

Which existing KUTs are useful for this user need, and in what order?

It must consider:

- relevance
- priority
- angle
- point of view
- sender role
- recipient role
- relationship
- occasion
- use case
- mood
- feeling
- delivery risk
- exclusion flags
- platform purpose
- end-user goal

## Relevance

Relevance measures how strongly the exact KUT audio fits the user’s purpose.

Relevance is based on the KUT audio itself.

Do not assign relevance from PIX title alone.

Do not assign relevance from folder path alone.

Do not assign relevance from holiday campaign history alone.

## Priority

Priority controls display and workflow order.

Priority may consider:

- user urgency
- emotional safety
- best first listen
- confidence
- prior approval
- delivery readiness
- theme strength
- business readiness
- platform purpose

Priority does not change the KUT.

Priority only changes how the system presents or handles the KUT.

## Angles

An angle explains why a KUT may work.

Examples:

- gratitude
- remembrance
- repair
- steady support
- romantic warmth
- fun lift
- quiet comfort
- proud respect
- western backbone

## POV

POV identifies the emotional viewpoint.

Examples:

- sender to father
- child to parent
- partner to partner
- friend to friend
- recipient self-keep
- grief remembrance
- apology without pressure

## MSP rule

MSP means user-facing music service/product route.

MSP must be cogent, end-user focused, and emotionally useful.

MSP does not manipulate.

MSP does not force choices.

MSP gives clear choices and lets the user decide.

MC-BOT guides by user input, questions, and direction.

## Backend required fields

Each silo row must preserve:

- silo id
- theme id
- KUT / KK id
- parent PIX id
- exact audio path
- relevance score
- priority tier
- angle
- POV
- use case
- sender role
- recipient role
- platform purpose
- user goal
- exclusion flags
- approval status
- delivery render status
- public label
- internal notes

## Display law

PIX pages display PIX titles.

KUT / KK buyer displays use theme/use-case labels.

Backend preserves PIX lineage.

## Locked instruction

Do not create duplicate KUTs for themes.

Do not detach KUT audio from PIX lineage.

Do not allow broad metadata loops to replace exact KUT metadata.

Do not let holiday names rename PIX titles.

All theme silos point to existing KUTs.
