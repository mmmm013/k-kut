# DISCO → 4PE Feature Parity Checklist

## Goal

4PE replaces the useful operational functions of DISCO while adding GPMx-specific governance.

DISCO is current paid infrastructure/reference.
4PE is target owned architecture and eventual infrastructure.

## DISCO Functions To Match

- audio upload
- audio playback
- share link
- embed/share page
- download permission flag
- playlist/package grouping
- artwork
- lyrics/notes/metadata
- private/public access control
- catalog browsing
- simple presentation for recipients/collaborators

## 4PE Functions Beyond DISCO

- PIX-PCK backend package
- CC Copy-Capture mechanism from exact PIX SSOT URL
- II production/anchoring
- KK governance
- KK-Combo contiguous-only governance
- one governed selection per purchase
- no user rearrangement
- HUG/TUG emotional delivery
- MC-BOT guided selection
- Admin promotion gates
- rights/ASCAP-aligned reporting support
- backend-only lineage/audit

## Replacement Readiness Tests

4PE can replace DISCO for a PIX only when:

- PIX audio plays from owned SSOT
- lyrics/metadata are stored
- share page works
- embed/share behavior is acceptable
- download permission is controlled
- PIX-PCK exists
- Admin can review/approve
- KKs/KK-Combos are governed
- CC/II lineage is preserved on backend
- frontend hides backend machinery
