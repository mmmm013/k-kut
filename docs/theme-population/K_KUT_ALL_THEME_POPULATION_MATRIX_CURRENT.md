## Purpose

Populate k-kut.com across all buyer themes without repeating the A Love like That failure.

This matrix controls theme expansion, recursive refinement, and bad-KK replacement.

## Core rule

Ownership is not the blocker.

Section accuracy, lineage, and buyer trust are the release gates.

## Source use rule

IN/O-PIX:
Used for KKr learning only.

IN-PIX:
Used for training section behavior, lyric structure recognition, genre behavior, and IN/O comparison.

LT-PIX:
Used for public KK / K-KUT / HUG products only after section proof.

## Population levels

L0:
Theme route exists, no public audio.

L1:
Theme has LT-PIX candidates.

L2:
Theme has section-mapped LT-PIX.

L3:
Theme has approved public KK / HUG options.

L4:
Theme has recursive refinement, bad-KK replacement, play reporting, and PIX-PCK rollup.

## Recursive refinement loop

Every public KK / HUG must support:

1. user play
2. play reporting
3. parent PIX / PIX-PCK rollup
4. bad-KK report
5. defect category
6. free replacement when defect is confirmed
7. recut or retire
8. updated section registry
9. updated public route
10. new build/audit proof

## Bad-KK defect categories

Free replacement applies when a customer reports and review confirms:

- start too early
- start too late
- end too early
- end too late
- resolving note cut off
- musical tail cut off
- wrong section
- wrong emotional match
- audio artifact / glitch
- dead audio link
- wrong HUG delivered
