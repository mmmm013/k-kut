# MC-BOT Transaction and Voice Grooming System

## Locked Doctrine

BOT-driven user transaction is required.

MC-BOT drives the buyer transaction.

MC-BOT voice is an optional excellence layer.

K-KUT / HUG audio remains the product.

The platform does not require an English dictionary recorded in MC's voice.

## MC-BOT Transaction Role

MC-BOT greets the user on arrival and begins a guided transaction.

The transaction path includes:

1. arrival greeting
2. ask user's name
3. identify interest / occasion
4. identify recipient or use case
5. identify intended feeling
6. condition and normalize user input
7. feed normalized intent into KKr
8. process IIs
9. present suitable K-KUT / HUG options
10. require listening before purchase
11. guide selection
12. guide checkout
13. guide delivery

## KKr Connection

MC-BOT does not merely display buttons.

MC-BOT gathers user signals and feeds them into KKr for:

- interest identification
- feeling intent
- phrase / word / sound matching
- II processing
- conditioning
- normalization
- option narrowing
- K-KUT / HUG selection support

## Voice Grooming Rule

MC-BOT voice should be groomed from available real-source MC material.

Sources may include:

- existing BOT prompt clips
- interviews
- guide recordings
- phrases
- sentences
- fragments
- words
- vocal sounds
- breaths
- tone samples

The goal is not to record every possible sentence.

The goal is to build a categorized voice asset library.

## Voice Asset Categories

Each groomed voice asset should be tagged by:

- transcript
- word / phrase / sentence / sound
- transaction intent
- flow step
- tone
- emotion
- volume
- pace
- duration
- clarity
- confidence
- public suitability
- replacement need
- risk notes
- source file
- source start time
- source end time

## Playback Rule

MC-BOT voice must not block the transaction.

MC-BOT voice must not autoplay.

MC-BOT voice must not play over K-KUT / HUG audio.

MC-BOT voice must not replace the K-KUT.

MC-BOT voice must not become the product.

If no suitable voice asset exists, MC-BOT continues silently using text and buttons.

## Excellence Standard

MC-BOT should feel guided, calm, intelligent, and specific.

MC-BOT should not chatter.

MC-BOT should not require the user to understand the platform.

MC-BOT should reduce confusion.

MC-BOT should ask the next sensible question.

MC-BOT should route every answer toward KKr processing and a useful HUG outcome.

## Product Truth

MC-BOT is the guided transaction agent.

KKr is the processing and normalization system.

IIs are conditioned and normalized expression inputs.

K-KUT / HUG audio is the product.

Voice is a groomed presentation layer.
