# 4PE / KKr / HUG Scenario Map

## Core Doctrine

General → narrower → narrower → fitting choices → user satisfied → checkout.

The system must guide users from broad human feeling into precise emotional fit.

The user should never need to understand metadata. The system and guide should translate feeling into fitting choices.

## Current Flagship Invention Stack

1. 4PE — customizable operating mechanism for intake, processing, cataloging, matching, delivery, and audit.
2. KKr — customizable mechanism for song-section / feeling / option generation and review.
3. K-KUT — user-facing purchasable emotional music moment.
4. HUG — digital audio greeting card built from real human-created music and K-KUT options.

## Primary User Scenario — Buyer

User wants to send feeling.

Path:

1. Welcome / guided explanation
2. Pick broad purpose
3. Pick finer emotional lane
4. Pick fitting song set
5. Pick K-KUT moment
6. Confirm
7. Checkout
8. Receive playable HUG link

Risk:
User gets lost, sees too many choices, sees wrong choices, or cannot play.

Required design:
One step at a time. One question at a time. Only fitting choices.

## Confused User Scenario

User does not understand HUG.

Path:

1. User clicks “I don’t understand”
2. System routes to demo
3. Demo lets user hear and see the product
4. User can return to guided flow or buy live HUG

Risk:
Demo takes over normal flow.

Required design:
Demo is available, not intrusive.

## Returning User Scenario

User has already heard welcome.

Path:

1. Skip pushed welcome
2. Offer optional replay
3. Start at guided choice

Risk:
Welcome becomes annoying.

Required design:
Founder/guide welcome plays only when requested after first listen.

## Mobile Streaming Scenario

User is on phone and wants immediate audio.

Needs:

- Fast loading
- Tap-to-play only
- One audio at a time
- No overlapping audio
- No browser audio bars unless useful
- Clear Play / Choose buttons
- No auto-play dependency

Risk:
Mobile browsers block autoplay, audio overlaps, or user cannot tell what is playing.

Required design:
Every play action is user-tapped. Every new play stops and resets all other audio.

## Gifting Scenario

User wants to send a HUG to someone else.

Needs:

- Clear emotional fit
- Simple confirmation
- Playable link
- Future SMS only after Twilio approval
- Email/social/direct link support

Risk:
User thinks SMS is guaranteed before Twilio approval.

Required design:
Promise playable HUG link. Do not promise SMS until approved.

## Social / Media Channel Scenario

User wants to share by social link, DM, text, email, or post.

Needs:

- Shareable HUG URL
- Clean title
- Clear preview
- Emotional label
- Song / K-KUT context
- No internal metadata leakage

Risk:
Public share looks unfinished or confusing.

Required design:
Public HUG pages must explain the feeling, song moment, and action simply.

## Artist / Catalog Scenario

User wants full tracks or artists.

Needs:

- Clear bridge to G Putnam Music
- Full track / artist access
- K-KUT remains focused on HUG / K-KUT products

Risk:
K-KUT and G Putnam Music become muddled.

Required design:
K-KUT = focused emotional audio greeting / K-KUT delivery.
G Putnam Music = full tracks, artists, catalog, deeper music context.

## Sponsor / Charity Scenario

Charitable support must be permission-based.

Current status:
Scherer family support activity is ON HOLD by family request.

Rule:
Do not publish, solicit, promote, or process charity/support activity without explicit approval.

## Metadata Scenario

The system must refine by:

- Feeling
- Mood
- Synonym
- Relationship
- Occasion
- Intensity
- Situation
- Recipient
- Tone
- Theme
- Lyric meaning
- Vocal energy
- Song section
- Emotional arc
- User behavior
- Rejections / another-set requests

Rule:
Quantity never beats fit.

The finer the emotional match, the more valuable the HUG.

## “Another Set” Scenario

User does not like the first set.

Path:

1. User asks for another set
2. System shows next fitting set
3. No filler
4. User can loop, go back, or ask guide

Risk:
System repeats wrong songs or adds unrelated songs.

Required design:
Another set must mean another fitting set, not random expansion.

## Missing Preview Audio Scenario

A K-KUT option exists, but preview audio is not loaded.

Correct copy:
Preview loading.

Do not show:
Dead Play button.
Coming soon.
Fake audio.
Internal label.

## Checkout Scenario

User confirmed one HUG.

Required copy:
This order includes one selected HUG.

Do not show:
18A.
ASCAP explanation.
Internal rules.
Unclear restrictions.

## Leadership Goal

K-KUT / 4PE / KKr should lead by making a new invention feel obvious.

The platform should make users feel:

- I know what to do.
- I am being guided.
- These choices fit my feeling.
- I can hear before choosing.
- I can ask for another set.
- I can go back.
- I can buy when it feels right.
